# PaperRadio 기능명세

> 구현된 것을 기준으로 쓴 문서다. 계획이 아니라 **현재 동작**과 그 근거를 남긴다.
> 실측으로 확인한 값과 함정에는 근거를 함께 적었다 — 나중에 같은 실수를 반복하지 않기 위해서다.

## 0. 설계 원칙

### 0.1 보기와 읽기를 분리한다

```
PDF ─┬─▶ 보기 : pdf.js canvas + 텍스트 레이어  ──▶ 원본 페이지 그대로
     │
     └─▶ 읽기 : 텍스트 추출 → rawText(SSOT) ──▶ 문장 청크 → TTS
                        ↕
        텍스트 레이어 span 에 문자 offset 을 심어 두 층을 잇는다
```

원본을 그대로 그리므로 **어떤 PDF든 화면은 정상**이고, 추출 품질은 *듣기에만* 영향을 준다.
2단 조판이 뒤섞여도 보이는 것은 멀쩡하고, 스캔본조차 읽기(보기)는 완벽하다.

파생 이점: 낭독용 텍스트가 화면에 렌더되지 않으므로 머리말 제거·줄 병합 같은 정리를
자유롭게 할 수 있다.

### 0.2 좌표계는 셋, 진실은 하나

| | |
|---|---|
| ① PDF 내부 | `(page, item index)` — pdf.js 가 주는 것 |
| ② **rawText offset** | `[start, end)` — **단일 진실(SSOT)**. 청크·북마크·하이라이트가 사는 곳 |
| ③ DOM span | `data-start` / `data-end` — 텍스트 레이어 |

②는 원본 PDF 바이트가 아니라 **추출기가 조립한 문자열**이다. 그래서 머리말을 버려도
offset 이 어긋나지 않는다(버린 것은 애초에 rawText 에 없다).

대신 **재현성**이 생명이다. 같은 PDF + 같은 `EXTRACT_VERSION` 이면 언제나 같은 rawText 가
나와야 저장된 북마크가 유효하다.

### 0.3 버전 필드 둘

| 상수 | 범위 | 바뀌면 |
|---|---|---|
| `EXTRACT_VERSION` (`pdf/extract.ts`) | PDF → rawText | **offset 좌표계 자체가 달라짐 → 북마크 무효** |
| `REFINE_VERSION` (`refine/index.ts`) | rawText → chunks | 청크 캐시만 재생성(북마크는 유효) |

## FN-01 · PDF 입력

- **MUST** 드래그앤드롭 + 파일 선택 둘 다 지원한다.
- **MUST** 진행 상황을 표시한다. 136쪽 문서는 페이지 순회에 체감 시간이 있어, 표시가 없으면
  멈춘 것처럼 보인다. 단계는 `여는 중 → 텍스트 읽는 중(n/N쪽) → 문장 나누는 중 → 저장 중`.
- **MUST** 20MB 초과 시 한 번 확인받는다(추출 시간과 저장 용량이 함께 커진다).
- **MUST** 원본 PDF 바이트를 함께 저장한다. 정독뷰가 원본을 다시 그려야 하고, 텍스트 레이어
  offset 도 같은 원본에서 재생성하기 때문이다.
- 문서 제목은 PDF 메타데이터의 `Title` 이 쓸 만하면 그것을, 아니면 파일명을 쓴다.
  제작 도구가 넣은 무의미한 값(`untitled`, 파일 경로류)은 거른다.

> ⚠️ pdf.js 는 넘긴 ArrayBuffer 를 transfer 해 **호출측 버퍼를 detach** 시킨다.
> 원본을 따로 보관하므로 파싱에는 `slice(0)` 복제본을 넘긴다.

## FN-02 · 텍스트 추출 (`pdf/extract.ts`)

MarkdownRadio 의 `refineMarkdown()` 자리를 대신한다. 산출물(`CleanBlockEx[]`)을 그대로
`chunkify()` 에 넘기면 이후 파이프라인이 무수정으로 재사용된다.

### 실측 근거로 정한 규칙 4가지

한국어 PDF 2종(34쪽·136쪽)을 뜯어보고 정했다.

**① item 순서 ≠ 읽기 순서 → 좌표로 재정렬**

검사한 문서는 꼬리말이 본문보다 **먼저** 나왔다.

```
2쪽 item 순서:  (41,22) "VLM/VLA 개인 구상 검토본"  ← 꼬리말이 맨 앞
                (374,22) "2"
                (41,535) "읽기 전에"                ← 본문은 그 다음
```

순서대로 이으면 매 쪽 꼬리말이 본문 앞에 낭독된다. → y 내림차순, 같은 줄은 x 오름차순.

**② 머리말/꼬리말은 쪽수만큼 반복 → 제거**

136쪽 문서는 모든 쪽 하단에 `문서명 + 쪽번호` 가 있었다. 제거하지 않으면 **136번 낭독**된다.

판정은 두 조건을 **함께** 본다:
- 위치 — 페이지 상·하단 8% 안
- 반복 — 숫자를 뺀 텍스트가 40% 이상 쪽에서 동일

위치만 보면 본문 첫/끝 줄을 지우고, 반복만 보면 우연히 반복되는 본문을 지운다.

**③ 한국어 줄바꿈은 공백 없이 붙인다**

```
"…장면의 변화를 해석"  +  "한 뒤, 그 결과로…"
        → "해석한 뒤"  (O)      "해석 한 뒤"  (X)
```

한국어는 **낱말 중간에서도** 줄바꿈되므로 영문 규칙(공백)을 쓰면 어색해진다.
구분 단서는 **줄이 우측 끝까지 찼는지(좌표)** 뿐 — 텍스트만으로는 불가능하다.

여유값 trade-off(실측):

| 여유 | 결과 |
|---|---|
| 0.5글자 | `"해석한 뒤"` ✅ 이지만 `"어떻 게"` 처럼 **낱말이 갈라지는** 새 오류 |
| **1.5글자** (채택) | `"어떻게"` ✅, 대신 `"위험을검토하기"` 처럼 어절이 붙는 오류가 소수 |

검사한 문서는 낱말 중간 절단이 압도적으로 많아 **붙임 우선**이 오류가 적었다. 낭독 품질로도
붙는 쪽이 낫다 — 한국어 TTS 는 붙은 어절은 무난히 읽지만 갈라진 낱말은 어색하게 끊는다.

**④ 하이픈 분철 병합** — 영문에서 `infor-` + `mation` → `information`.
하이픈 1자를 rawText·piece·블록텍스트 **세 곳에서 함께** 되돌린다.

### 🔴 계약: 이음 문자도 piece 다

`chunk.ts` 는 `pieces` 를 이어붙여 텍스트를 재구성한다(`buildOffsetMap`). 따라서
`CleanBlockEx` 의 계약 **"text === pieces 의 plain 연결"** 을 어기면 안 된다.

줄 이음 공백을 blockText 에만 넣고 piece 로 넣지 않았더니 URL 이 있는 청크에서 FN-03 이
깨졌다. **블록·조각은 일치하는데 청크만 어긋나면 이걸 의심할 것.**

### 성능 (실측)

| 문서 | 결과 |
|---|---|
| 34쪽 한국어 | rawText 18,535자 · 블록 86개 · **15ms** |
| 136쪽 한국어 | rawText 101,261자 · 블록 770개 · **138ms** |

두 문서 모두 블록·조각 전건 일치, FN-03 통과, 꼬리말 잔존 0회.

## FN-03 · 청크와 offset 불변식

`chunkify` 이하(문장 분리·offset 매핑·불변식·발음 규칙)는 MarkdownRadio 에서 그대로 가져왔다.

**불변식(MUST · 강제)** — 모든 `kind==='speech'` 청크에 대해:

```
normalizeForCompare(rawText.slice(c.startOffset, c.endOffset)) === normalizeForCompare(c.text)
```

- 프로덕션은 위반 시 `console.warn` 만 하고 청크를 그대로 쓴다(graceful — 앱을 죽이지 않는다).
- 회귀는 `npm run test:extract <pdf>` 가 `strict` 모드로 잡는다. **프로덕션만 보고 "괜찮다"고
  판단하면 안 된다.**

## FN-05 · 정독뷰 — 원본 페이지 렌더

### 가상화는 선택이 아니다

A4 를 DPR 2 로 그리면 **페이지당 약 7.6MB**. 20쪽만 상주해도 150MB 라 모바일에서 무너진다.

- 화면 밖 페이지는 `canvas.width = 0` 으로 픽셀 버퍼를 즉시 반환한다.
- 요소와 예약 높이는 남긴다 — 스크롤 위치가 흔들리지 않게.
- 히스테리시스: 로드 마진 600px < 언로드 마진 1500px (경계 떨림 방지).

### 모바일 안전장치 셋

| | 이유 |
|---|---|
| **렌더 직렬화** | 자매 프로젝트에서 모바일 GPU 가 동시 추론을 못 버티고 멈췄다. 페이지 렌더도 promise 체인으로 한 번에 하나씩 |
| **DPR 상한 2** | DPR 3 을 그대로 쓰면 픽셀이 2.25배 |
| **재생 중 페이지 언로드 제외** | canvas 를 해제하면 그 위 텍스트 레이어·하이라이트까지 사라진다 |

### 실측으로 잡은 함정 셋

1. **flex 아이템이 짜부라져** 페이지 예약 높이가 29px 로 붕괴 → `flex: 0 0 auto`
2. **IntersectionObserver 가 순간 이동 스크롤에서 언로드를 놓친다**(끝까지 점프 시 앞쪽 2쪽
   잔류) → 스크롤이 멎으면 한 번 쓸어 담는 안전망
3. **탭 전환 직후 첫 렌더가 슬롯보다 10% 작은 해상도로 굳는다** → 리사이즈 감시를 컨테이너가
   아니라 **각 페이지 슬롯**에 걸어 어긋난 페이지만 재렌더

### 자리 예약

`pageRanges` 에 페이지 크기(width/height)를 저장하고 `aspect-ratio` 로 높이를 미리 잡는다.
없으면 페이지가 그려질 때마다 높이가 변해 스크롤이 튄다.

## FN-06 · 폐루프 — 하이라이트와 클릭 재생

원본 위에 **투명 텍스트 레이어**를 얹고 각 span 에 rawText offset 을 심는다.
그래서 좌표 계산 없이 두 방향이 성립한다.

### offset 을 "저장"하지 않고 "복원"한다

조각 정보는 문서 하나가 수만 개가 될 수 있어 저장하지 않는다. 대신 같은 추출 로직을
**그 페이지에만** 다시 돌려 상대 offset 을 얻고, 저장된 rawText 안에서 위치를 찾아
절대 offset 으로 옮긴다(`computePageSpanOffsets`).

**재현성 조건**: `runningHeads` 와 `bodySize` 를 저장된 값 그대로 주입해야 한다. 한 쪽만
넣으면 글자 크기 중앙값이 달라져 헤딩 판정 → 블록 경계 → 줄 이음까지 어긋난다.

복원에 실패하면 **레이어를 만들지 않는다** — 페이지 보기는 유지되고 폐루프만 조용히 빠진다.
잘못된 위치로 점프하는 것보다 낫다.

### 하이라이트는 걸치는 span 을 모두 칠한다

PDF 텍스트는 **시각적 줄 단위**로 쪼개져 있어 "가장 좁은 요소 하나"만 고르면 문장의 한 줄만
칠해진다. 범위와 겹치는 span 을 전부 칠한다(실측: 한 문장이 3개 span).

### 표시가 사라지는 함정

가상화로 텍스트 레이어가 지워졌다 다시 만들어지면 붙여 둔 클래스가 **함께 날아간다**
(실측: spanCount 가 0→16→0→24 로 오갔다). 하이라이트·점프 위치를 **상태로 들고**,
레이어가 새로 생길 때마다 다시 칠한다.

### 검증 (실측)

span offset 32건 **전건 설명됨** — 정확 일치 28 + 하이픈 분철 4(의도된 1자 차이), 미설명 0.

## FN-07 · 재생 제어

`ReadingControls` 는 렌더러와 **완전히 무관**하다 — 재생 상태와 콜백만 받는다.
청취 화면(Player)과 같은 상태를 보므로 두 화면의 조작이 어긋나지 않는다.

정독뷰에서 쓸 수 있는 것:

| 기능 | 동작 |
|---|---|
| ▶ / ⏸ | 재생·일시정지 |
| 🔁 | 한 문서 반복 |
| ↔ 구간 | 현재 위치 기준 A → B → 해제 순환 |
| 더블클릭 | 그 문장부터 즉시 재생 |
| 단클릭 | 그 문장으로 이동(더블클릭과 겹치지 않게 250ms 지연) |
| 자동 스크롤 | 재생 중에만 따라간다(`block:'nearest'` — 이미 보이면 안 움직인다) |

> 상태 소유 원칙: 재생 상태(playing·repeat·A-B)는 **App 이 단일 소스**로 갖고,
> Player/정독뷰는 표시와 버튼만 담당한다.

## FN-08 · 북마크

- 저장 단위는 `(청크 인덱스, 청크 내 상대 offset)`. 점프할 때 절대 offset 으로 환산한다.
- 점프 재트리거는 **nonce** 로 구분한다 — 같은 북마크를 다시 눌러도 이동해야 하는데 offset 만
  비교하면 값이 그대로라 반응하지 않는다.
- 점프 강조는 재생 하이라이트와 **다른 색**을 쓰고 `block:'center'` 로 가운데에 놓는다
  (찾아온 위치를 확실히 보여준다).

> ⚠️ Svelte `$effect` 에서 `!a || !b || !c` 처럼 **조건 안에서 값을 읽으면 short-circuit 으로
> 의존성 추적이 끊긴다.** 탭을 열자마자 점프하면 문서 로드 전에 한 번 돌고 끝나 강조가 영영
> 안 붙었다. 의존성은 조건 앞에서 전부 읽을 것.

## FN-09 · 페이지 넘김 모드

| 모드 | 동작 |
|---|---|
| 연속(기본) | 페이지가 세로로 이어짐. IntersectionObserver 로 가상화 |
| 넘김 | 한 번에 한 쪽. 커서로 직접 관리, **상주 canvas 는 항상 1장** |

넘김 모드에서 인접 쪽을 미리 그리지 않는 이유: 숨긴 요소는 폭이 0 이라 해상도를 잘못 잡는다.

**재생 따라가기** 스위치 — 재생이 다음 쪽으로 갈 때 화면도 따라갈지. 읽던 쪽이 강제로 바뀌면
흐름이 끊기므로 끌 수 있어야 한다.

> ⚠️ 따라가기 effect 가 `pageCursor` 를 읽으면 **▶ 버튼이 먹지 않는다** — 사용자가 넘기는
> 순간 effect 가 다시 돌아 재생 위치로 되돌린다. `activePage` 직전 값과만 비교한다.

> ⚠️ 정독뷰는 탭을 옮겨도 **지우지 않고 숨기기만** 한다. 매번 지웠다 만들면 보던 쪽이 1쪽으로
> 리셋되고 원본 PDF 도 다시 파싱해야 한다.

## FN-10 · 스캔본(텍스트 없는 PDF)

텍스트 레이어가 없으면 읽을 문자가 **존재하지 않는다**. 원천적으로 낭독이 불가능하다.

- 가져오기를 **실패로 처리하지 않는다** — 청크 0개인 "보기 전용" 문서로 저장한다.
- 문서를 열면 곧바로 정독 탭으로 간다(들을 게 없으므로).
- 청취 탭은 비활성 + 안내 문구.
- 원본 페이지 보기는 **완벽히 동작**한다.

OCR 도입은 보류 상태다. 구조는 열어 두었다.

## 데이터 모델

### `StoredDocument` (IndexedDB `documents`)

| 필드 | 설명 |
|---|---|
| `rawText` | 추출된 낭독용 원문 — **offset 좌표계의 기준**. 화면에 렌더되지 않는다 |
| `chunks` | 문장 청크(캐시). `refineVersion` 이 다르면 재생성 |
| `lastChunkIndex` | 이어듣기 위치 |
| `pdf` | `PdfMeta` — 아래 |

### `PdfMeta`

| 필드 | 왜 저장하는가 |
|---|---|
| `pageRanges` | 페이지 ↔ rawText 범위. "이 청크가 몇 쪽인지" 판정 + 페이지 크기로 자리 예약 |
| `runningHeads` | **페이지 단독 재추출 시 주입 필수** — 없으면 offset 이 어긋나 북마크가 깨진다 |
| `bodySize` | 위와 같은 이유(헤딩 판정 기준) |
| `emptyPages` | 스캔본 판정 |
| `extractVersion` | 다르면 offset 좌표계 자체가 달라진 것 |

### 스토어 구성

| 스토어 | 내용 |
|---|---|
| `documents` | `StoredDocument` |
| `pdfBlobs` | **원본 PDF 바이트**. documents 와 분리한 이유는 라이브러리 목록 조회가 수십 MB 를 끌고 오지 않게 하기 위해서다 |
| `bookmarks` | `documentId` 인덱스로 문서별 조회 |
| `settings` | 전역 설정 1건 |

문서를 지우면 원본·북마크까지 **한 트랜잭션에서** 함께 지운다.

## 배포·번들

- precache 는 앱 셸(약 290KB)만. TTS 모델(`.onnx`)과 pdf.js 청크(433KB)는 의도적으로 제외한다.
  모델은 `modelCache.ts` 가 IndexedDB 로 자체 캐시하므로 SW 가 손대면 중복 저장이 일어난다.
- **COOP/COEP 헤더는 지우면 안 된다.** 교차출처 격리가 없으면 SharedArrayBuffer 가 꺼져
  추론이 **빈 버퍼(무음)** 를 낸다. 배포본에서 `crossOriginIsolated === true` 확인.

자세한 절차는 [deploy-cloudflare.md](deploy-cloudflare.md).

## 개발 중 알아 둘 것

### 자동화 브라우저에서 pdf.js 렌더가 멈춘다

pdf.js 는 `intent:'print'` 가 아니면 rAF 로 렌더를 스케줄하는데, 자동화 브라우저는
문서가 `hidden` 이라 rAF 가 돌지 않아 **렌더가 영원히 대기**한다.

`src/lib/debug/rafShim.ts` 가 **dev 에서만** setTimeout 으로 대체한다. 프로덕션은 무변경 —
백그라운드 탭에서 렌더를 쉬는 것은 정상이자 바람직한 동작이다(탭으로 돌아오면 이어진다).

### 검증 도구

```bash
npm run test:extract <pdf경로>        # 추출 → 청크 → FN-03(strict) 회귀 검사
node tools/inspect-pdf.mjs <pdf경로>  # 새 PDF 의 item 구조 진단(분절 단위·hasEOL·2단 여부)
node tools/make-sample-pdf.mjs        # 의존성 없는 검증용 픽스처 생성
# 앱 아이콘(PNG) 재생성 — sharp 는 빌드에 불필요하므로 의존성에 두지 않는다
npm i -D sharp && node tools/make-icons.mjs && npm uninstall sharp
```

## 아직 하지 않은 것

- **2단 조판 컬럼 분리** — 논문에서 좌우 컬럼이 뒤섞여 읽힌다(화면은 정상). 좌표 기반 분리 필요.
- **OCR** — 스캔본 낭독.
- 키보드 내비게이션 — 텍스트 레이어 span 이 수백 개라 단순 `tabindex` 는 오히려 방해가 된다.
  별도 설계가 필요하다.
